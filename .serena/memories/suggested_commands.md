# Suggested commands

From the repo root:
- `pnpm install`; `cp .env.example .env` and set `ORLOK_SECRET_KEY=$(openssl rand -base64 32)` (server refuses to start without it; tsx watch reads `.env` only at start: restart `pnpm dev` after changing it)
- Reset the dev DB completely: `docker exec orlok-db-1 psql -U orlok -d orlok -c 'truncate table messages, conversations, colleagues, office_members, offices, sessions, settings, model_profiles, model_providers, users cascade'` (ask first: the user keeps real data there)
- E2E against the dev DB without touching the user's account: insert a temporary admin (hash with `node -e 'import("@node-rs/argon2")…'` from `apps/server`), log in with curl, create test data through the API, then delete the test office and user
- Headless screenshots of authenticated pages: temporary `apps/web/public/_login.html` that sets localStorage, POSTs `/api/auth/login` with a test account and redirects; delete it afterwards. Log in with `remember: true`, or a second Chrome run with the same profile is signed out. Headless Chrome does not render narrower than about 500px: for phone width put the page in an `<iframe>` 390px wide inside a second temporary page, which can also click through `iframe.contentDocument` (e.g. to open a collapsed card). Scrolling inside the app is unreliable: use a tall window and crop the image. On Windows, stopping a background `npx vite`/`tsx` task leaves the server running: free the port with `taskkill //PID <pid> //T //F` (pid from `netstat -ano`), and kill leftover `chrome.exe` of a scratch profile before deleting it
- `pnpm db:up` / `pnpm db:down` — Postgres 18 + pgvector (`compose.dev.yaml`, dev only)
- `pnpm dev` — server (tsx watch, :3000) + Vite (:5173 on all interfaces, `strictPort`, proxies `/api` → :3000). Reachable from the LAN at the machine's address; set `ORLOK_PUBLIC_URL` in `.env` to it for invitation links
- Dev runner: ignores `.env` and uses the built-in token `orlok-dev-runner-token`. A different `ORLOK_RUNNER_TOKEN` in `.env` makes every server→runner call fail with 401. On Windows `pnpm dev` stops at the runner (POSIX env syntax in its script), so start server and web separately (README). The runner started natively on Windows accepts jobs but fails them with `spawn /bin/sh ENOENT`; run it from its Docker image to try operations
- `pnpm lint` (Biome check), `pnpm check` (Biome with fixes). On a Windows checkout (`core.autocrlf=true`, files CRLF) both flag every file for line endings and `pnpm check` rewrites ~400 files to LF: run `pnpm exec biome check --write <changed files>` instead; to undo a repo-wide rewrite, `git checkout` the files `git status` lists as M but `git diff` does not
- Reset a password from the server (R-AUTH-7): `pnpm --filter @orlok/server reset-password --email <x> [--database URL]`; in production `docker compose exec app orlok-reset-password --email <x>`. Never against the dev DB without asking (the user keeps real data there)
- `pnpm typecheck`, `pnpm test`, `pnpm build`
- Single package: `pnpm --filter @orlok/server <script>` (`@orlok/web`, `@orlok/shared`)
- Migrations: after changing `apps/server/src/db/schema.ts` → `set -a && . ../../.env && set +a && pnpm db:generate` inside `apps/server`; migrations apply automatically at server start and in test setup. tsx watch does not restart on new migration files: touch `apps/server/src/index.ts`
- Renames (a table, or a column dropped and another added in the same table) make `db:generate` ask which it is, and it needs a TTY: it fails in an agent shell. Two ways out — split the change so each generation only adds or only drops (add the new column, generate, then drop the old one, generate), or write the SQL by hand and derive the snapshot from the previous one (copy `meta/<prev>_snapshot.json`, apply the renames, set `prevId` to the previous `id` and a fresh `id`, add the `_journal.json` entry). Then run `db:generate` once more: "No schema changes" proves the snapshot matches `schema.ts`. Data conversion SQL can be appended to a generated file, statements separated by `--> statement-breakpoint`
- Going back to an older image after a release that changed the schema: the image tag alone is not enough, since migrations only go forward. A release with a schema change ships a rollback script (with the app stopped, it undoes the migration and removes its rows from `drizzle.__drizzle_migrations` by the `when` of `meta/_journal.json`), rehearsed on a scratch database like the migration; a migration that drops data has none, and going back is the previous image plus a dump taken just before the release
- A migration that drops or rewrites data is rehearsed on a copy of the production data before the release, on its own server: `CREATE DATABASE orlok_rehearsal` in the database container, `pg_dump -U orlok orlok | psql -d orlok_rehearsal` inside the container, the migration files piped to `psql -v ON_ERROR_STOP=1 -1`, then the counts, then `DROP DATABASE`. The data never leave the server
- While main carries work that must not be released yet, a fix needed in production goes on a branch from the released commit, is tested with the Linux CI and released with the next free tag; main gets the same fix on its own
- `pkill -f <pattern>` kills the agent's own shell when the pattern appears in its command line (exit 144): kill by `pgrep -f "^/usr/lib/chromium/chromium"` or `"^node …"` instead
- Headless screenshots: run each page with `timeout 40` and its own `--user-data-dir`; one page can hang `--virtual-time-budget` forever
- Rehearse a migration that rewrites data on a scratch database: `create database orlok_rehearsal`, apply the files up to the previous one with `docker exec -i orlok-db-1 psql -U orlok -d orlok_rehearsal < 00xx_*.sql`, seed rows like production's, apply the new ones, look at the result, drop it
- Reset the dev DB (back to first-run setup): `docker exec orlok-db-1 psql -U orlok -d orlok -c 'truncate table sessions, settings, users cascade'`
- Postgres 18: mount the volume on `/var/lib/postgresql`, not `/var/lib/postgresql/data`
- Serena language servers (typescript) are read from `.serena/project.yml` only when the MCP server starts: after changing that file restart the Claude Code session, otherwise symbolic tools fail with "Active language servers: []"
- Dependencies with build scripts (e.g. esbuild) must be allowed in `pnpm-workspace.yaml` → `allowBuilds`, otherwise pnpm 11 fails with ERR_PNPM_IGNORED_BUILDS
- Headless screenshots to check themes/languages: `chromium --headless=new --no-sandbox --window-size=1280,1000 --virtual-time-budget=8000 --screenshot=<file> <url>`. `--lang` is ignored (browser language comes from the system locale): force `localStorage["orlok-theme"|"orlok-locale"]` through a temporary page in `apps/web/public/` that redirects to `/`, then delete it. `--disable-gpu` with a scrolling page can draw white rectangles: use a taller window
