# Conventions

## Language
- Everything in the repo is English: identifiers, comments, docs, test titles, API messages, commit messages. Exception: `apps/web/src/i18n/locales/it.ts`.
- Commits: imperative mood ("Add…", "Fix…"); commit and push only when the user asks.

## Requirements
- Every feature maps to an ID in `docs/REQUIREMENTS.md` (also in comments, e.g. `// R-UI-3`); new requirements go into the document first.

## Formatting
- Biome (2 spaces, 100 columns). Workspace packages scoped `@orlok/*`; logic shared by server and web goes to `packages/shared`.

## Server (Hono)
- `createApp(deps)` with explicit dependencies (`Deps` = db + config, `src/types.ts`); startup, migrations, shutdown in `src/index.ts`
- Routes per area in `src/routes/<area>.ts` as `new Hono<AppEnv>()`, mounted in `app.ts` under `/api`
- Inputs validated with `validate(target, schema)` (`src/lib/validation.ts`) using zod schemas from `@orlok/shared`
- Current user via `currentUser(c)` after `requireUser`
- Integration tests with `app.request()` on the test DB, `resetDatabase` in `beforeEach`

## API errors (R-I18N-4)
- Body `{ code, message, issues?: [{ path, code }] }` built with `errorBody()` (`src/lib/errors.ts`); `code` from `ERROR_CODES`/`ISSUE_CODES` (`packages/shared/src/errors.ts`); English technical `message`
- In zod schemas the message is the issue code (`{ error: "required" }`); unknown messages map to `invalid_value`
- Issues may carry numeric `params` (e.g. `{ max: 64000 }`) for the translated message; `translateFieldErrors` formats them per locale with defaults (`min` = password length, `max` = output token limit)
- Token usage: `inputTokens` must be the whole prompt. The Anthropic adapter sums `input_tokens` with the two cache fields (`promptTokens` in `llm/anthropic.ts`), because with prompt caching on — some gateways turn it on — `input_tokens` alone counts only what the cache did not serve (a dozen tokens) and the context meter never moves; OpenAI's `prompt_tokens` already includes them
- Model limits: `ProviderModel.maxOutputTokens` comes from the provider (Anthropic Models API `max_tokens`; null for OpenAI-style APIs and Meridian); profile saves reject values above a published limit (`exceeds_model_limit`), unknown limits pass
- Web translates with `translateError`/`translateFieldErrors` (`src/i18n/errors.ts`). New code → add it to `errors.codes`/`issues` in every locale

## Models and secrets
- Model calls only through `Deps.llm` (`LlmClientFactory`, default `createLlmClient`); tests inject a fake factory instead of hitting providers
- Adapters always pass the API key explicitly (never let SDKs read `ANTHROPIC_*`/`OPENAI_*` from the host env)
- Provider keys and future credentials: store with `encryptSecret`, decrypt only when building a connection (`connectionFor`); API responses expose `hasApiKey`, never the key
- Admin API under `/api/admin/*` behind `requireAdmin`; streaming responses are SSE with one JSON `ChatStreamEvent` per `data:` line (`streamSSE` server side, `streamApi` in the web)
- Provider failures are reported as data (`{ ok: false, message }` for listing, `error` stream event for chat) with `describeProviderError`

## Offices, colleagues, conversations
- Office access: administrators see every office; members only offices in `office_members` (`canAccessOffice`, `listWorkspaceOffices` in `services/offices.ts`). Always check access through these, never by role alone
- Conversations are private to their owner and also require current office access; unknown or foreign ids answer 404 (not 403)
- Personal colleagues (R-ADM-3, since 2026-10-05): `colleagues.user_id` = owner, `archived_at`, `deleted_at` (tombstone: name + owner kept so wiki/audit authorship survives; conversations, attachments, instructions, profile deleted and pending jobs/plans stopped by `deleteColleague`; the owner's approved command types stay), unique `(user_id, office_id, lower(name))` among non-deleted. Helpers in `services/colleagues.ts`: `findOwnColleague` (owner + office access, archived included), `findWorkingColleague` (background work: active and owner not disabled), `isActive`, `profileGranted`. Routes `routes/colleagues.ts` on `/colleagues`: `GET /profiles` (granted to me), `POST /` (`officeId` in body), `GET/PATCH/DELETE /:id` (own only, 404 otherwise; PATCH `archived`). Admin has no routes for personal colleagues and `AdminOffice` lists none (only the office colleague, below). Workspace lists own colleagues plus the office colleague, `archived` separately, with `needsProfile`. Web: what concerns the colleague sits on its row in `OfficeNav` (settings button over the row, to `/colleagues/:id/_settings`, archived too), the chat keeps what concerns the conversation (selector, new, rename, delete, `ContextMeter`) plus the archived/no-profile notice that unblocks it (since 2026-10-06)
- Office colleague (R-ADM-8, migration 0041): `colleagues.office_wide` true, partial unique index `colleagues_office_wide_idx` on `office_id` among non-deleted (the owner-name index now excludes it); `user_id` is only its creator. Admin routes `POST|PATCH|DELETE /api/admin/offices/:id/colleague` (any profile, no `notes`), `AdminOffice.colleague`. `findOwnColleague` excludes it (members cannot change it); `findTalkableColleague` (own or office colleague not archived, with office access) for conversations, attachments and `GET /colleagues/:id` (instructions blanked); `needsProfile` only when its profile is gone; `resolveColleagueModel` skips grants for it; `findWorkingColleague`, document filing, wiki reflection and save-to-wiki never use it. Turn: tools only `wiki_search` + `wiki_read`, no notes/ops/MCP, `OFFICE_COLLEAGUE_INSTRUCTIONS` before the admin's instructions. Workspace and Telegram list it for everyone in the office (first in `OfficeNav`, `UsersRound` icon); `colleagueSettingsPath` gives settings only to admins (others read "not available")
- Colleague model: `resolveColleagueModel(db, colleague)` joins `profile_grants` of the owner: no profile or not granted → null; sending then answers 409 `colleague_needs_profile`, disabled provider 409 `model_not_configured`, archived 409 `conflict`
- Profiles (R-MOD-2, since 2026-10-05): `model_profiles` = provider + model + `mode` (EXEC_MODES deny/ask/full/yolo), unique per combination (`model_profiles_combination_idx`, 409 issue `profile_exists` on `mode`); PATCH renames only; DELETE refused with `profile_in_use` while a person is granted it or it is the documents' vision profile (colleagues on it are left with `profile_id` null). `profile_grants` (user → profile) and `invitation_profiles` (granted on acceptance) are edited in People (`profileIds`) and enforced, administrators included (create/PATCH a colleague with an ungranted profile → 400 issue `not_granted`). Creating a profile grants it to nobody. Migration 0030 granted each owner the profiles of their active colleagues, so the colleagues an installation had kept answering after the plan's release. Web: own admin page `/admin/profiles` (`pages/admin/ProfilesPage.tsx`, `features/profiles/*`, `ModeBadge`), the name is suggested from model + mode
- Message flow: store user message → build history (user messages + complete assistant messages only) → stream → store assistant message with status `complete`/`stopped`/`error`, error code, model and token usage
- System prompt built only in `buildColleagueSystemPrompt` (English; the owner's instructions last inside `<instructions>`; reply in the writer's language, R-I18N-5), followed in a chat turn by the `<operations>` section of `opsInstructions` (`ops/tools.ts`): how to use the command tools with the approval line of the mode; in deny mode that the profile allows no commands; without tools, the hosts where the person has no credential. Both tool branches end with `talkingAboutTargets(locale)`: a missing credential is answered in a sentence or two pointing to `CREDENTIALS_PAGE[locale]` (the person's UI language, `user.locale`, passed to `opsInstructions` and `OpsToolContext.locale`), other hosts only if asked, no comments on keys from the wiki, the runner never named to the person. The identity line also says not to assume the person's gender. None when there is no host and no runner
- Web chat: `ChatView` keyed by colleague; leaving a conversation (another tab, the list) lets go of its answer in a `useLayoutEffect` before paint (abort, bump `watchRef`, clear `pending`/`streaming`), the server keeps writing and coming back follows it (`running` → `follow`); only creating a new conversation at the first message (`creating` = streaming without pending) locks switching. Pending exchange shown until the conversation query is refetched. Stored messages go through `StoredMessage` (`memo`, props = the message object as the query keeps it + primitives; attachments and save target built inside): every key typed re-renders ChatView, and redrawing every bubble's Markdown made typing take ~1 s per key in a 400-message conversation (2026-10-30). Never pass objects or arrays built in ChatView's render to it. Scroll follows the end (`followEnd`, held by a ResizeObserver) until the view moves up away from the end (a shrinking transcript clamps the view but leaves it at the end, so it does not count); `send()` always follows again
- Code blocks: `Markdown` maps fenced `pre` to `CodeBlock` (language label, copy, Shiki highlighting debounced during streaming). `features/chat/highlighter.ts` uses `shiki/core` + JavaScript regex engine, themes from `@shikijs/themes` rendered together as CSS variables (`defaultColor: false`, colors picked per `[data-theme]` in `index.css`), and an explicit curated `LANGUAGES` map from `@shikijs/langs` plus `ALIASES`. Never import `shiki`, `shiki/langs` or `shiki/themes` bundles: they emit every grammar/theme chunk and huge grammars (cpp, emacs-lisp) trigger the >500 kB build warning. Unsupported languages render as plain text

## Office wiki (R-MEM)
- Routes `src/routes/wiki.ts` under `/api/offices/:officeId/wiki` (overview, search, log, pages/:slug, revisions, restore, import). Access only via `getWikiAccess` (`services/wiki.ts`): admins and office managers edit, other members read, everyone else 404
- Slugs are permanent and unique per office (`WIKI_SLUG_PATTERN`, `slugify` in `packages/shared/src/wiki.ts`); links are `[[target]]`/`[[target|label]]`, target slugified; `extractWikiLinks` ignores code and feeds `wiki_links` (by target slug, target may not exist)
- Every write goes through `insertPage`/`savePageRevision` (revision row, links, `search` tsvector) plus `appendLog`; updates require `baseRevision` → 409 `revision_conflict`; restore saves the old content as a new revision
- Search (R-MEM-4): ranked in the app, no tsvector (dropped in 0025). `services/wiki-search.ts` (pure, unit-tested): `buildSearchIndex` + `rankPages` = BM25-style with length normalization, 6-letter prefix stems (final vowel dropped in 5-6 letter words), exact bonus for long identifiers (idf gain over the prefix), IPs/hosts/paths/codes matched whole as substrings, 2-3 letter terms only as whole words or endings, synonym groups counted once (`WIKI_SEARCH_SYNONYMS` in shared + office `wiki_synonyms`, `parseWikiSynonyms`), outdated pages ×0.5. `searchPages` caches the index per office by page count + max updated_at. Keep short IT terms (AD, VPN) out of the stopword list
- Demo (`demo/`, see demo/README.md): fictional Acme for the website and presentations, never real data, not in the image (`.dockerignore`). `demo/compose.yaml` (db 127.0.0.1:5544, app `orlok:demo` 127.0.0.1:3999, fake runner `demo/screenshots/demo-runner.mjs`) + `demo/setup.sh [--build]` (secrets in `demo/.env`, drops and reseeds `orlok_demo` every run). Seed `demo/seed/demo-seed.ts` = workspace package `@orlok/demo-seed`, imports server code by relative path, so `pnpm typecheck` covers it: update it with schema/classifier changes. It marks the nightly wiki lint as done today (`wiki_lint_last_day`), or the lint would close its 192.0.2.x review items a minute after start. Playwright scripts in `demo/screenshots` (own package.json, outside the workspace): `shoot.mjs` → `demo/output/site` (14), `shoot-video.mjs` → `demo/output/video` (36, `--theme light` → `demo/output/video-light`, one run per fresh seed); outputs are committed
- Measure before changing retrieval: `pnpm --filter @orlok/server wiki:eval --database <copy> --office <name> --questions <tsv> [--misses]` (`src/cli/wiki-eval.ts`, `services/wiki-eval.ts`) prints recall@1/@k/MRR for words, meaning and final. Questions (a TSV of question and expected page) are written for a real office and kept with its data, never in the repository; run against a local copy (`orlok_eval` DB: migrate, then COPY that office's offices/wiki_pages/wiki_links/wiki_embeddings rows with `session_replication_role = replica`), never production. Baseline 2026-09-30: final 84% @1, 99% @5, MRR 0.896
- Page status and verification (R-MEM-13): `wiki_pages.status` (current/superseded/retired/historical) + `verified_on` date, both also in revisions and restored; colleagues mark replaced text with `> **Superseded (date):** old → new`; the colleague prompt carries `Today is …`
- Colleague writes (R-MEM-3): `wiki_edit` (exact replacement, count must match) and guarded `wiki_write` (`services/wiki-guard.ts`: refuse <70% of a page ≥1500 chars unless `allow_shrink`; report lost links/headings/IPs/dates/backtick values; similar titles on create)
- Lint without model (`services/wiki-lint.ts`, kinds in WIKI_LINT_KINDS, auto-closed): `ip_conflict`, `stale_page` (>365 days), `relative_date`, `missing_entity` (host in ≥4 pages without page). `wikiHealth` + `GET /wiki/health`. Model kinds (`WIKI_MODEL_REVIEW_KINDS` = `check`): never swept, and once done/dismissed by a person never reopened
- Critical reading (R-MEM-14) `services/wiki-check.ts`: `POST /wiki/review/check {colleagueId}` → 202, background, 5 pages, quote must be in the page, `reviewed_revision` skips unchanged pages. Updates that must not bump `updatedAt` ($onUpdate) set it explicitly to the old value
- Ingest outcome (R-MEM-15): analysis ends with `## Outcome` (new/update/contradiction/nothing, `parseIngestOutcome`); "nothing" skips filing and the overview; stored in `wiki_sources.outcome`
- Proposals (R-MEM-16) `services/wiki-reflect.ts` worker (10 min): conversations quiet >1h and <14 days, ≥4 user messages since last reading, no wiki edits → ≤3 `conversations.wiki_candidates`, shown only to the owner (`WikiCandidates` in chat), `POST|DELETE /conversations/:id/wiki-candidates/:index` (save = queued markdown source with the transcript). Private conversations never go to the office review queue
- Chat: before streaming, `listPages` + `findContextPages` go into `buildColleagueSystemPrompt({ wiki })` (`<wiki>` block, reference data not instructions, cite `[[slug]]`); a `context` SSE event is sent first and pages are stored in `messages.wiki_pages`. Clients handling `ChatStreamEvent` must not treat unknown types as errors
- Import (`services/wiki-import.ts`): Markdown files only, shared root folder dropped, folders → section, frontmatter `title/type/section/sources/slug` (yaml), relative `.md` links → wiki links, one transaction, same slug → new revision or unchanged, one `import` log entry
- Web: routes `/offices/:officeId/wiki` (`pages/wiki/*`, `_new`, `_import`, `_log` reserved because slugs cannot start with `_`, `:slug`, `:slug/edit`, `:slug/history?rev=N`); `WikiLayout` provides `useWiki()` outlet context; `Markdown` renders wiki links when `wikiBase` is set (`wikiTitles`, `markMissing`)

## Tool use and wiki maintenance by colleagues (R-MEM-3)
- `LlmClient.streamChat` accepts `tools` and `LlmMessage` (user / assistant with `toolCalls` + opaque `providerData` / tool results) and emits `tool_calls` chunks; Anthropic sends back thinking blocks via `providerData`; OpenAI accumulates streamed tool call deltas. `eager_input_streaming` is left off because compatible proxies (Meridian) may reject it; Meridian supports tools
- `runAgent` (`services/agent.ts`) is the only tool loop: streams text, runs tools, feeds results back until an answer without tools or `maxSteps`. Tools throw `ToolInputError` for problems the model can fix (returned as `isError` results); other errors fail the run
- `createWikiTools` (`services/wiki-tools.ts`): `wiki_search`, `wiki_read`, `wiki_write` scoped to one office and authored by the colleague; updates require `base_revision` of the current page; `findLikelySecret` (`services/secrets.ts`) blocks credentials (the Markdown/Joplin import instead masks them with `redactSecrets` and reports `secretsRemoved`; measured on a real Joplin notebook against a hand redaction: 22 of 22, no extra); every write adds a source (conversation or document) and a log entry. `mergeEdits` dedupes edits per page
- Chat: default memory policy `WIKI_MEMORY_INSTRUCTIONS` is always in the colleague prompt (consult first, decide alone when to update, no secrets, tell the person); SSE adds `tool` and `wiki_edit` events; edits stored in `messages.wiki_edits`
- Documents: `POST /offices/:id/wiki/sources` (multipart `files` + `colleagueId` = one of the uploader's own active colleagues in that office with a granted profile, managers/admins; same check for `/wiki/review/check`) extracts text with `extractDocument` (`src/documents`) into `wiki_sources` (queued); `startWikiIngestWorker` in `index.ts` runs `processNextWikiSource` (claims with `for update skip locked`, splits long text with `splitIntoParts`, ingest prompt `buildIngestSystemPrompt`: source page `doc-<title>` + topic pages). Tests call `processNextWikiSource` directly. Multipart requests in tests need an `Origin` header (Hono csrf)
- Upload stores the original file (`wiki_sources.data`, bytea) with its `sha256` (unique per office → `duplicate` rejection) after `detectDocumentFormat`; nothing is extracted in the request. The worker reads it (stage `extracting`, `extractDocument` with OCR languages mapped from `SUPPORTED_LOCALES` via `OCR_LANGUAGES_BY_LOCALE`), resolves image/page markers with `applyDocumentImages` (`services/vision.ts`: optional vision profile from settings key `documents`, `/api/admin/documents`; pages lowest-OCR-confidence first, decorative images dropped, OCR kept on failure; stage `describing`), stores `content`, then files (stage `filing`). Retry clears `content` so the document is read again. Failures carry `errorCode` (`WIKI_SOURCE_ERROR_CODES`) translated in the web, raw `error` shown only for provider/internal errors
- `LlmMessage` user content may be `LlmContentPart[]` with base64 images (Anthropic image blocks, OpenAI `image_url` data URLs); Meridian accepts images
- Never select `wiki_sources.data`/`content` in lists (`sourceColumns` in `services/wiki-ingest.ts`)

## Memory links, graph, review
- `services/wiki-graph.ts`: `computeGraph` (pure, unit-tested) builds weighted undirected edges from links, shared sources (sources cited by >25 pages ignored), Adamic-Adar over link neighbors, type affinity (only on already related pairs) and semantic kNN pairs; weights `WIKI_RELEVANCE_WEIGHTS` in shared; Louvain communities with a seeded rng (renumbered by size); insights (surprising = cross-community edges, isolated = degree ≤ 1, bridges ≥ 3 communities, sparse = cohesion < 0.15 and size ≥ 3). `getWikiGraph` caches per office by a key over page/embedding counts and max updated_at. `relatedPages`, `expandScores` (2 hops, halved, scaled by weight)
- `services/wiki-retrieval.ts`: `retrievePages` = full-text (weak matches < 25% of best rank dropped) + semantic (`semanticSearch`, relative threshold) fused with RRF, then graph expansion; used by `wiki_search` and `retrieveContextPages` (chat context). Failing embedding providers never break answers
- Built-in embeddings (`src/embeddings-local`, default mode `builtin`): onnxruntime-web (WASM, no install scripts, glibc+musl) + @huggingface/tokenizers running `Xenova/multilingual-e5-small` quantized in a worker thread (prefixes, 500-token chunks, mean pooling). Model files are NOT in git: `pnpm --filter @orlok/server models:fetch` downloads the pinned revision with SHA-256 check into `apps/server/models` (or `ORLOK_MODELS_DIR`); the Dockerfile must run it in a build stage. Worker bundled as `dist/embeddings-worker.mjs` (tsdown entry). `ORLOK_EMBEDDINGS_THREADS` (default half the cores, max 8); ~1.6 GB RSS with the model loaded. Injected as `Deps.localEmbedder` (tests pass `async () => null`)
- `services/embeddings.ts`: settings key `embeddings` with `mode` builtin/provider/off, `Embedder.embed(texts, "query" | "document")` with per-model prefixes (`withInputPrefix`: e5, nomic, qwen3, embeddinggemma); table `wiki_embeddings` (pgvector `vector` without fixed dimension, `page_updated_at` compared with `date_trunc('milliseconds', updated_at)` because JS dates have ms precision); `startEmbeddingWorker`; migration 0008 creates the extension
- Review queue `services/wiki-review.ts`: lint findings keyed (`isolated:<slug>`, `sparse:<hub>`, `broken:<target>`), refreshed, auto-closed when gone, dismissed ones never reopened; colleagues raise `contradiction`/`missing_page`/`question` with the `wiki_flag` tool. Lint runs after each ingest and on demand
- Ingest is two-step (`buildAnalysisSystemPrompt` without tools with retrieved related pages, then `buildIngestSystemPrompt` tool loop with the analysis); a missing source page `doc-<title>` is created from the analysis; `updateOverview` maintains slug `overview`; office purpose (`offices.wiki_purpose`) goes into chat and ingest prompts
- `services/wiki-cascade.ts`: `deleteSourceWithPages` (source tag `Document: <file>`; delete source pages and pages with no other source, remove tag from shared ones, strip links to deleted pages outside code). `DELETE /wiki/sources/:id?cascade=true`
- Save answer: `POST /conversations/:id/messages/:messageId/wiki` queues a markdown source (dedup by sha256 → 409)
- Web: `_graph` (`WikiGraph.tsx`, sigma + graphology + ForceAtlas2 worker, palette `--graph-1..12` in index.css), `_review`, `WikiPurpose` on home, related pages on page view, delete choice in documents, "Save to the wiki" under answers
- "Fix with <colleague>" (`WikiReview.tsx` `fixPrompt`, keys `wiki.review.fixPrompt.intro/pages/ask`): a plain request, `[[links]]` of the detail replaced by page titles, pages listed only when the detail does not name them, no item id (the colleague finds it with `wiki_review_list`). It lands in the chat box, which grows with its text (`useLayoutEffect` on `draft` in `ChatView`, up to `max-h-60`)
- Tests with the SSE chat endpoint must read the response body: tools run while the stream is consumed

## Operations (R-OPS, after OpenClaw exec approvals)
- Runner `apps/runner`: separate container, internal HTTP API (Bearer `ORLOK_RUNNER_TOKEN`), jobs + SSE stream + stop, MCP stdio bridge; per-job uid via setpriv launcher, prlimit, masked output. Server side only through `Deps.runner` (`ops/runner-client.ts`, null when not configured; tests inject a fake). `pnpm dev` runs it on 127.0.0.1:3100 with the dev token
- Tables credentials (a person's own since 2026-10-05: `user_id`, unique name per user; encrypted, revealed only to hand to the runner), credential_hosts (credential × host with `user_id` repeated, unique user + host = one credential per person per host; cascades on credential/host/user), (the web tests a credential on each of its enabled hosts right after saving it: `CredentialForm` `onDone(saved)`, `HostRow autoTest`; results are not stored), hosts (one registry, no office, unique `lower(name)`; the machine alone: SSH, host key TOFU, `resetHostKey`), (colleague_ops_policies dropped in block 3: the runner and the office's enabled MCP servers are there in every mode but deny, no admin rules for everyone), approved_command_types (a person's "allow always" since block 4: user + shell + type, valid with all their colleagues on every host and the runner; `disabled_at`, `disabled_by_admin`; cascade on user), mcp_servers, ops_jobs (`host_id`, target kind runner/host/mcp), audit_events (append-only, never secrets; write via `ops/audit.ts`)
- `ops/classifier.ts` + `rules.ts` + `command-types.ts`: `classifyCommand(command, shell, { mode, approvals })` parses POSIX (unbash AST) and PowerShell (own tokenizer) into `pieces`; DENY_RULES block in every mode but yolo (also through wrappers, inside PowerShell script blocks). Ask mode (block 4): each piece is a read (READ_ONLY_RULES + `readOnlyObjection`) or gets a type (`commandType`: program + 1-3 words from `POSIX_WORDS`/`POWERSHELL_WORDS`, options skipped, Windows /switch counts; `sudo`/`doas` prefix the type; timeout/nice/nohup/time/stdbuf transparent; a `>` write is the piece `WRITE_TYPE`); allow when every piece is a read or in `approvals.approved` (`typeKey`: PowerShell case-insensitive), else ask with `classification.types` = missing types. PowerShell (D1, 2026-10-11) is read as statements (`psStatements` → keywords if/foreach/for/while/do/try/function/param, `psAssignment`, pipelines whose first segment may be an expression, `psElement` for groups, `$( )`, strings, hashtables, types and members, `PS_SAFE_TYPES`/`PS_STATIC_METHODS`/`PS_SAFE_METHODS`); functions with a dash defined at the top are read once and their calls are not pieces; a script with no command at all is `valuesOnly` (allow); a sensitive literal anywhere makes file readers once only. `opaque` (POSIX substitutions, interpreters incl. by path, scripts, ssh, eval, su/env/xargs/watch…, `find -exec`, awk system, background, a variable in a type word, other .NET methods/types, property or special-variable assignments, `switch`, the call operator, Import-Module/aliases, `ForEach-Object <member>`) or a sensitive read or an admin-disabled type → `onceOnly: true`. Bare `sc` is Set-Content (Windows PowerShell), `sc.exe` the service tool. Reasons stay technical English (the colleague reads them); `explainReason` (`packages/shared/src/ops-reasons.ts`) maps them to `OPS_REASON_CODES` for the web (`JobReason.tsx`, `chat.ops.reasons.*`), and `ops/reasons.test.ts` checks every reason literal in classifier.ts has a code: a new reason needs a pattern and both translations. The mode comes from the colleague's profile: ops code takes a `WorkingPolicy` = `{ mode }`, built in `runColleagueTurn`
- `ops/jobs.ts`: `requestJob`/`requestMcpJob` → pending_approval or queued; `decideJob` once/always (`approveTypes` saves `classification.types` for `requestedForUserId` unless `onceOnly` or MCP; types are audited in `job.approve` detail)/deny; `requestJob` classifies with `typeApprovalsFor` the requesting user (`ops/approved-types.ts`); atomic `claimJob` by the tool or `startOpsWorker`; interrupted running jobs fail at startup; late results reach the colleague via `continueAfterJob` (`services/colleague-turn.ts`, also the single chat turn implementation)
- Output while running (2026-10-13, R-CHAT-4): `runner.wait(..., { onProgress })` (polling only) gives each running state; `executeJob` saves `maskLikelySecrets(output)` at most every `PROGRESS_SAVE_MS` (2 s) `where status = 'running'`, `finish()` then overwrites it. `jobResultsForHistory` leaves the output of running jobs out. The card (`OpsJobCard`) shows only `chat.ops.linesSoFar` in the badge, and `chat.ops.alwaysAllowed` (small, muted; a `CheckCheck` icon with title in the folded line) when `classification.decision === "allow"`, no `decidedBy` and `matchedRules` has `type:` entries
- `ops/hosts.ts` (was `nodes.ts`): host registry CRUD (audited with `officeId: null`), `allowedHosts(db, userId, policy)` = enabled hosts where the requesting person has a credential, with that credential. `ops/vault.ts`: personal credentials (`listCredentials`/`findCredential` by user, `hostsProblem`, `deleteCredentialsOf` on disable, `credentialIdForHost` read in `executeJob` with `requestedForUserId`, not at request time, so a removed credential stops a waiting approval). The colleague never names a credential: it acts as the person, which stops the "permission denied → retry as root" move. ## People, invitations, email
- Invitation tokens reuse the session token helpers: random token in the link, only its SHA-256 in `invitations.token_hash`; usable = not accepted, not revoked, not expired (`findUsableInvitation`)
- Creating an invitation revokes pending ones for the same email; resend rotates token and expiry; the response always includes `inviteUrl` plus `email` status (`sent` / `not_configured` / `failed`) so admins can share the link manually (`InviteResultCard` shows it at once only when the email did not leave, otherwise behind "Show link"; keyed by `inviteUrl` so a resend starts over)
- Accepting creates the user with the invitation's role, locale and office memberships in one transaction and signs them in
- Password resets (R-AUTH-7, `services/password-resets.ts`): admin `POST /api/admin/people/:id/password-reset` → `PasswordResetResult` (`resetUrl` `/reset-password/<token>` only when the email did not leave, `null` once it left so the admin never holds the link; email status as invitations, via `deliverLinkEmail` in `services/invitations.ts`); table `password_resets` (token SHA-256, one row per person: a new link deletes the old); sessions end when the link is made (the admin's own current session kept when resetting themselves); disabled → 409 `person_disabled`. Public `GET|POST /api/password-resets/:token` (preview; set password → deletes sessions and links, signs in). Server CLI `src/cli/reset-password.ts` (`dist/reset-password.mjs`, `orlok-reset-password` in the image): random password printed once, `resetPasswordFromServer`. Audit actions `person.password_reset_link|password_reset|password_reset_server`, installation log. The old password keeps working until the link is used (decided 2026-10-22). After every password change (link, server command, `PATCH /me/password`) `notifyPasswordChanged` emails `passwordChangedEmail` (how = link/server/account, no links inside) through `deliverLinkEmail`, best effort: the change stands when it does not leave; the CLI prints whether it left (it needs `ORLOK_SECRET_KEY` to read the SMTP settings). Web: reset in `PersonRow` (confirm, then `LinkResultCard`, shared with `InviteResultCard`), `pages/ResetPasswordPage.tsx`
- Administrators are assigned no offices (they work in all, `accessibleOfficeIds` returns `"all"`), since 2026-10-06: the forms hide `MembershipsEditor` for the admin role and send none; the server saves none on a PATCH that leaves the person admin (promoting clears them), stores none on an admin invitation, skips them when accepting an older one, and `toPerson`/`toInvitation` report none for admins. A member (not admin, not disabled) with no office is "without office" (`features/people/without-office.ts`): badge on the row and a count next to People in `AdminLayout`; people with no granted profile get a blue `info` badge (Badge variant added 2026-10-08), distinct from the grey role badge. Without granted profiles (`useMyProfiles`) the side list and `WorkspaceHome` show whom to ask instead of the create links; `ColleagueForm` preselects a profile only when exactly one is granted
- Ended sessions: `errorFrom` in `lib/api.ts` calls the `onSessionEnded` listener on 401 `unauthenticated`; `main.tsx` then, only if `me` was set, marks it in sessionStorage (`lib/session-ended.ts`) and sets `me` to null, so the gate goes to `/login`, which shows the notice until the next sign-in
- Return after sign-in (2026-10-13, R-AUTH-1): `Gate` in `router.tsx` sends app → `/login` with `state: returnState(location)` and login → app to `returnPath(location.state)` (`lib/return-path.ts`: only paths starting with one `/`, never `/login` or `/setup`, else `/`). `useLogout` marks a sign-out on purpose (`markSignedOut`), which remembers nothing; `useLogin` clears it
- Disabled people: `users.disabled_at`; login rejected with `invalid_credentials`, sessions deleted on disable and rejected in `validateSession`. Admins cannot demote/disable themselves (`self_change_not_allowed`); `last_admin` guard kept as safety
- Email only through `Deps.mail` (`MailerFactory`, nodemailer in production, fake in tests); SMTP settings in `settings` key `smtp` with encrypted password (`services/smtp.ts`); templates in `apps/server/src/mail/templates.ts` per locale, HTML escaped
- Links in emails use `config.publicUrl` (`ORLOK_PUBLIC_URL`, default `http://localhost:5173`)
- CSRF origin (`app.ts` `requestOrigins`): form-like posts pass with an Origin equal to the request URL, `ORLOK_PUBLIC_URL` or the forwarded host (`X-Forwarded-Host`/`Host` + `X-Forwarded-Proto`); the Vite dev proxy uses `xfwd: true`, and a production reverse proxy must forward these headers. Plain http on a LAN address sends no Sec-Fetch-Site
- Hono `csrf()` treats requests without Content-Type as form posts: browsers pass thanks to `Sec-Fetch-Site`, but curl DELETE/POST without JSON body gets 403 — send `-H 'Content-Type: application/json'` or an Origin header in manual tests
