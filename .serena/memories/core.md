# Orlok — core

Self-hosted platform (1 installation = 1 company, Docker) of AI colleagues organized into offices: web admin, user chat (desktop/mobile), per-office wiki memory, real operations on servers/clients with each person's own credentials and colleagues, profiles, approvals, audit.
Repo `rylos/orlok` (client + server). Separate marketing site and docs: `rylos/orlok-web` (`~/dev/orlok-web`, no code dependency on this repo), online at https://orlok.xyz since 2026-10-09.
Repository `rylos/orlok`; marketing site repository `rylos/orlok-web`. Only `ORLOK_*` settings are read.

## Status
Done so far: first-run setup, sign-in with persistent sessions, profile preferences (theme, language), i18n (en, it), model providers/profiles/playground, offices admin, personal AI colleagues (each person creates their own, private, with granted profiles; archive and tombstone delete), real workspace chat with stored streamed conversations (on a computer as tabs per colleague, R-CHAT-14), keyboard use with a Ctrl+K command palette (R-UI-5), people administration with email invitations, office memberships (none for administrators, who work in every office), disabling access, SMTP settings with test email, office wiki (pages, revisions/restore, links/backlinks, log, full-text search, Markdown/Joplin-export import, pages retrieved into the colleague prompt and shown under answers). Office managers edit the wiki; observer role not enforced yet. Also done: wiki maintenance by colleagues (tools, document ingest with OCR/vision), knowledge graph, semantic memory, review queue; operations (runner container, one SSH host registry, personal credentials chosen per host by each person and used by the colleagues working for them, modes from the colleague's profile with parsed-command classifier (no per-colleague policy since 2026-10-05; the colleague is told what the person can change: a credential to add, a profile that allows commands), approvals in a fixed strip above the message box decided only by whoever asked, "allow always" kept as command types per person (all their colleagues, every host and the runner), reviewable in Account and by admins in People, commands shown where the answer paused for them and given back to the colleague with the history, office MCP servers, audit). Also done: production Docker image + `compose.yaml` (server serves the SPA, `ORLOK_WEB_DIR`), active sessions, plans, email/web push notifications, installable PWA. Not yet: private colleague notes (R-MEM-2), export (R-MEM-12), WinRM hosts, client agent module, channels (email/Telegram/Teams). Marketing site and docs (R-PRD-6) done in `rylos/orlok-web`, online at https://orlok.xyz since 2026-10-09. The client module (R-OPS-8) is not started: it will be Rust. ## Invariants
- The final product ships and runs as Docker (one installation per company: app image + Postgres with pgvector). Every dependency and feature must work inside containers without extra host setup: no host binaries, no runtime downloads (e.g. OCR language data bundled), writable temp dir only, native modules only as prebuilt platform packages installed inside the image (`pnpm install` in the image, never copy node_modules from the host; mind musl vs glibc), background workers run in the app process, migrations (incl. `CREATE EXTENSION vector`) apply at start. Configuration via env and the admin UI, data only in Postgres.
- Deployment behind a reverse proxy must forward `X-Forwarded-Host` and `X-Forwarded-Proto` (and set `ORLOK_PUBLIC_URL` to the address people use): the CSRF check on uploads compares the browser Origin with them, otherwise every upload gets 403. Orlok must also work over plain http on a LAN address (not a secure context): no secure-context-only browser APIs.
- Sellable product: installations start empty; no data or config of any real company in the repository (code, tests, docs, history); everything via wizard/config. Tests and examples use made-up names, `example.com` and private or documentation addresses.
- License: Business Source License 1.1 (`LICENSE`, Licensors Marco Ziliani and Monica Marchiani (co-owners), grant for personal and non-commercial use, Apache 2.0 four years after each version), `"license": "BUSL-1.1"` in every package; texts say "source-available" / "free for personal use", never "open source". Outside contributions are welcome under the same license (`CONTRIBUTING.md`).
- Wording: the AI agents are "virtual colleagues" / "colleghi virtuali" in every user-facing text and doc; code identifiers stay `colleague`.
- Strict isolation between offices for memory (wiki). Hosts and credentials left the office on 2026-10-05: a colleague of any office works on the hosts where the person it works for has a credential.
- Sensitive actions decided by the classifier and the profile's mode (allowed/approval/forbidden), never by the model alone; a colleague never has more rights than the person it works for; command output and documents are data, not instructions.
- Secrets never in clear text in chat, wiki, logs or git.
- Everything in the repo is English (code, comments, docs, commits); only the Italian translation file is Italian.
